## مارکت‌پلیس دیدار چیست؟ {#what}

دیدار یک CRM است. هر شرکتی که از دیدار استفاده می‌کند یک فضای کاری جدا دارد که به آن **BizDomain** می‌گوییم. تیم‌ها داخل BizDomain با معامله‌ها، پرونده‌ها، اشخاص، شرکت‌ها و فعالیت‌هایشان کار می‌کنند.

**مارکت‌پلیس** راهی است که اپ‌های بیرونی به یک BizDomain وصل شوند و قابلیت جدید به دیدار اضافه کنند. **اپ** (یا پلاگین) در این داک یعنی هر وب‌اپلیکیشنی که روی سرور خودت اجرا می‌شود و:

- با اجازه‌ی ادمین روی یک BizDomain نصب می‌شود،
- به داده‌ی همان BizDomain دسترسی کنترل‌شده دارد،
- و از طریق **اکستنشن‌ها** داخل صفحه‌های دیدار دیده می‌شود.

چند مثال: ساختن جلسه‌ی آنلاین از روی یک معامله و ثبت لینکش در یادداشت‌ها، نمایش مانده‌حساب مشتری کنار پرونده‌ی شخص، یا ارسال چند معامله‌ی انتخاب‌شده به نرم‌افزار حسابداری.

## چرا برای دیدار اپ بسازی؟ {#why}

- **داخل جریان کار کاربر.** اپ تو در منوی عملیات معامله، شخص، شرکت و پرونده، یا به‌شکل پنل در صفحه‌ی جزئیات ظاهر می‌شود. کاربر برای استفاده از آن از دیدار بیرون نمی‌رود.
- **نصب با یک لینک.** ادمین لینک نصب را باز می‌کند، دسترسی‌ها را می‌بیند و با یک تأیید نصب می‌کند.
- **دسترسی دقیق و قابل‌فهم.** اپ فقط scopeهایی را دارد که ادمین تأیید کرده، و در هر اجرا فقط به رکوردهایی که کاربر باز یا انتخاب کرده.
- **بدون مدیریت token بلندمدت.** دیدار برای هر اجرا یک token کوتاه‌عمر می‌دهد؛ لازم نیست token کاربر را نگه داری یا refresh کنی.

## اپ چطور با دیدار کار می‌کند؟ {#how-it-works}

![Didar app lifecycle: register, install, launch, data](/images/flows/lifecycle.png "چهار مرحله؛ ثبت یک‌بار، نصب یک‌بار برای هر کسب‌وکار، اجرا و داده در هر استفاده")

| مرحله | کی اتفاق می‌افتد | چه کسی | نتیجه | جزئیات |
| --- | --- | --- | --- | --- |
| ۱. ثبت | یک‌بار | تو، در Developer Hub | Client ID، Client secret، لینک نصب | [Developer Hub](/developer-hub) |
| ۲. نصب | یک‌بار برای هر کسب‌وکار | ادمین کسب‌وکار | اپ به یک BizDomain وصل می‌شود با scopeهای تأییدشده | [جریان نصب اپ](/app-installation-flows) |
| ۳. اجرا | هر بار که کاربر اکستنشن را باز می‌کند | کاربر دیدار | سرور تو یک `launchCode` می‌گیرد و آن را به Runtime Token تبدیل می‌کند | [Runtime Token](/runtime-token) |
| ۴. داده | در طول هر اجرا | سرور تو | خواندن و نوشتن داده‌ی دیدار، فقط در محدوده‌ی scope و رکوردهای همان اجرا | [درباره‌ی API](/api-concepts) |

دو دامنه در این مسیر نقش دارند:

| دامنه | چه چیزی آنجاست |
| --- | --- |
| `https://app.didar.me` | خود دیدار: Developer Hub، صفحه‌ی تأیید نصب و endpoint تکمیل نصب |
| `https://marketplace.didar.me` | دریافت Runtime Token و همه‌ی APIهای داده |

> [!NOTE]
> **چرا launchCode؟** هیچ چیز حساسی نباید در URL یا مرورگر باشد. دیدار در URL فقط یک کد یک‌بارمصرف و بی‌ارزش می‌فرستد؛ token واقعی فقط بین سرور تو و مارکت‌پلیس رد و بدل می‌شود.

## یک اپ خوب چه ویژگی‌هایی دارد؟ {#good-app}

- **با زمینه کار می‌کند.** از رکوردی که کاربر در آن است (`context.entityIds`) شروع می‌کند، نه از یک فرم خالی.
- **جریان نصب تمیزی دارد.** ادمین بعد از نصب می‌فهمد چه شد و قدم بعدی چیست.
- **فقط دسترسی لازم را می‌خواهد.** هر scope را می‌تواند به ادمین توضیح بدهد.
- **پیام روشن می‌دهد.** در موفقیت و خطا، کاربر داخل دیدار پیام قابل‌فهم می‌بیند.
- **در هر دو تم خواناست.** UI اکستنشن‌های Custom در تم روشن و تیره‌ی دیدار درست دیده می‌شود.

## ساخت و مدیریت اپ {#managing}

اپ‌ها را در **Developer Hub** می‌سازی، ویرایش می‌کنی، Live می‌کنی و حذف می‌کنی. نگه‌داری اپ (کار کردن سرور، به‌روز بودن Callback URL و آدرس اکستنشن‌ها، پاسخ به مشکل کاربران) با سازنده‌ی اپ است. [Developer Hub](/developer-hub)

## اصطلاحات {#glossary}

| اصطلاح | معنی |
| --- | --- |
| BizDomain | فضای کاری یک کسب‌وکار در دیدار. هر نصب به یک BizDomain وصل است. |
| Developer Hub | بخشی از دیدار برای ساخت و مدیریت اپ‌ها؛ فقط برای ادمین BizDomain. |
| Client ID / Client secret | شناسه‌ی عمومی و رمز اپ. secret فقط روی سرور تو. |
| Callback URL | آدرس HTTPS اپ که دیدار بعد از تأیید نصب، `code` نصب را به آن می‌فرستد. |
| لینک نصب | آدرسی که ادمین را به صفحه‌ی تأیید نصب اپ می‌برد. |
| Scope | سطح دسترسی اپ به یک نوع داده، مثل `deals` یا `deals.fullaccess`. |
| اکستنشن | جایی از UI دیدار که اپ در آن ظاهر می‌شود. |
| Location | صفحه‌ای که اکستنشن در آن اجرا می‌شود، مثل «Deal details». |
| launchCode | کد یک‌بارمصرف و کوتاه‌عمری که دیدار هنگام اجرای اکستنشن به URL اپ اضافه می‌کند. |
| Runtime Token | JWT کوتاه‌عمری که سرور اپ با launchCode می‌گیرد؛ فقط برای همان اجرا. |
| Runtime Context | `target`، `runtimeId`، `location`، `entityType`، `entityIds` و `payload` همان اجرا. |
| ApiKey (کلید نصب) | کلیدی که پس از تکمیل نصب می‌گیری؛ فقط رمزگذاری‌شده نگه‌داری می‌شود. |
