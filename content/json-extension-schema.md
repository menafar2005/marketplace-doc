## این ساختار چیست؟ {#what}

وقتی اکستنشن [JSON modal](/json-modals) یا [JSON panel](/json-panels) را در Developer Hub اضافه می‌کنی، یک فایل JSON آپلود می‌کنی که می‌گوید فرم یا پنل چه بخش‌ها و چه آیتم‌هایی دارد. دیدار این فایل را اعتبارسنجی می‌کند و ظاهرش را با اجزای آماده‌ی خودش، هماهنگ با بقیه‌ی UI دیدار و در هر دو تم، می‌سازد. تو هیچ HTML، CSS یا JavaScriptی نمی‌نویسی.

نام رسمی این قرارداد **«ساختار اکستنشن جیسون دیدار نسخه‌ی یک»** است. این قرارداد با استاندارد عمومی `JSON Schema` فرق دارد: فایلی که تو آپلود می‌کنی خودش JSON Schema نیست، بلکه یک سند با قالب ثابت دیدار است. دیدار برای اعتبارسنجی این سند یک فایل JSON Schema منتشر کرده که [پایین‌تر](#machine-readable) آمده است.

## یک نمونه‌ی کوتاه {#quick-example}

```json title="form.json"
{
  "schemaVersion": 1,
  "layout": "form",
  "title": "ثبت درخواست پشتیبانی",
  "description": "اطلاعات درخواست را تکمیل کنید.",
  "loadOnOpen": true,
  "sections": [
    {
      "id": "request",
      "title": "اطلاعات درخواست",
      "items": [
        {
          "type": "text",
          "key": "subject",
          "label": "عنوان",
          "placeholder": "عنوان کوتاه درخواست",
          "required": true,
          "maxLength": 100
        },
        {
          "type": "select",
          "key": "priority",
          "label": "اولویت",
          "required": true,
          "options": [
            { "label": "عادی", "value": "normal" },
            { "label": "فوری", "value": "urgent" }
          ]
        },
        {
          "type": "textarea",
          "key": "description",
          "label": "توضیحات",
          "maxLength": 1000
        },
        {
          "type": "checkbox",
          "key": "confirmed",
          "label": "صحت اطلاعات را تأیید می‌کنم",
          "required": true
        }
      ]
    }
  ],
  "submit": {
    "label": "ثبت درخواست",
    "closeOnSuccess": true,
    "successMessage": "درخواست با موفقیت ثبت شد."
  }
}
```

## فیلدهای اصلی {#root}

| فیلد | اجباری | نوع | توضیح |
| --- | --- | --- | --- |
| `schemaVersion` | بله | عدد | در نسخه‌ی فعلی باید دقیقاً `1` باشد. |
| `layout` | بله | `form` یا `details` | رفتار محتوا را مشخص می‌کند ([پایین](#layout)). |
| `title` | خیر | [متن](#localized-text)، غیرخالی | عنوان بالای محتوا. |
| `description` | خیر | [متن](#localized-text) | توضیح کوتاه زیر عنوان. |
| `loadOnOpen` | خیر | boolean | اگر `true` باشد، دیدار هنگام باز شدن، داده‌ها را از سرور تو می‌گیرد ([extension.load](/api-app-endpoints#json-load)). |
| `sections` | بله | آرایه | یک تا بیست [بخش](#sections). |
| `submit` | خیر | object | تنظیمات دکمه‌ی ثبت برای فرم ([پایین](#submit)). |

در فایل ماشین‌خوان، هیچ سطحی از این ساختار ویژگی تعریف‌نشده نمی‌پذیرد؛ یعنی کلیدی که در این صفحه نیامده (یا اشتباه تایپی در نام کلید) باعث می‌شود فایل نامعتبر شود.

### layout {#layout}

| مقدار | رفتار |
| --- | --- |
| `form` | فرم قابل ثبت است؛ کاربر مقدار وارد می‌کند و با دکمه‌ی ثبت، مقادیر به سرور تو می‌رود. |
| `details` | فقط اطلاعات را نمایش می‌دهد؛ مناسب پنل‌های اطلاعاتی کنار رکورد. |

`layout` با **نوع نمایش** اکستنشن فرق دارد. نوع نمایش را در Developer Hub انتخاب می‌کنی: **مودال** (کاربر یک اکشن را انتخاب می‌کند و محتوا در پنجره باز می‌شود؛ [JSON modal](/json-modals)) یا **پنل** (محتوا بدون کلیک، در بخش اکستنشن‌های صفحه‌ی جزئیات نمایش داده می‌شود؛ [JSON panel](/json-panels)).

## بخش‌ها (sections) {#sections}

| فیلد | اجباری | نوع | توضیح |
| --- | --- | --- | --- |
| `id` | بله | رشته‌ی غیرخالی | شناسه‌ی بخش؛ باید در کل ساختار یکتا باشد. |
| `title` | خیر | [متن](#localized-text)، غیرخالی | عنوان بخش. |
| `description` | خیر | [متن](#localized-text) | توضیح بخش. |
| `items` | بله | آرایه | یک تا پنجاه [آیتم](#items). |

## آیتم‌ها (items) {#items}

هر آیتم یک `type` دارد. آیتم‌ها دو دسته‌اند: **ورودی** که کاربر مقدارشان را وارد می‌کند و **نمایشی** که فقط چیزی را نشان می‌دهند.

### آیتم‌های ورودی {#input-items}

| نوع | کاربرد |
| --- | --- |
| `text` | متن کوتاه |
| `textarea` | متن چندخطی |
| `number` | عدد |
| `date` | تاریخ |
| `select` | فهرست انتخابی |
| `radio` | انتخاب یک گزینه |
| `checkbox` | تأیید یا مقدار بله و خیر |

آیتم‌های ورودی باید `key` داشته باشند. `select` و `radio` باید `options` هم داشته باشند. ویژگی‌های اختیاری آن‌ها `label`، `placeholder`، `helpText`، `required`، `readOnly` و `defaultValue` است. محدودیت عددی با `min` و `max`، و محدودیت طول متن با `minLength` و `maxLength` تعیین می‌شود.

### آیتم‌های نمایشی {#display-items}

| نوع | کاربرد | الزامی |
| --- | --- | --- |
| `value` | نمایش یک مقدار دریافتی از سرور | `key` |
| `link` | نمایش لینک امن با پروتکل `http` یا `https` | `url` |
| `message` | پیام اطلاعاتی، موفق، هشدار یا خطا | `text` (غیرخالی) |
| `divider` | جداکننده‌ی بصری | - |

مقدار `value` با همان `key` از پاسخ [extension.load](/api-app-endpoints#json-load) سرور تو (`data.values`) خوانده می‌شود. برای `message`، ویژگی `variant` یکی از این مقادیر است:

```text title="variant"
info | success | warning | error
```

### همه‌ی ویژگی‌های آیتم {#item-properties}

| ویژگی | نوع | کاربرد |
| --- | --- | --- |
| `type` | یکی از `text`، `textarea`، `number`، `date`، `select`، `radio`، `checkbox`، `value`، `link`، `message`، `divider` | **الزامی برای همه.** نوع آیتم. |
| `key` | رشته‌ی غیرخالی | الزامی برای آیتم‌های ورودی و `value`. باید در **کل ساختار** یکتا باشد، نه فقط در یک بخش. |
| `label` | [متن](#localized-text) | برچسب آیتم. |
| `text` | [متن](#localized-text) | متن `message`؛ برای `message` الزامی و غیرخالی. |
| `url` | رشته‌ای که با `http://` یا `https://` شروع شود | الزامی برای `link`. |
| `placeholder` | [متن](#localized-text) | متن راهنمای داخل فیلد. |
| `helpText` | [متن](#localized-text) | توضیح زیر فیلد. |
| `required` | boolean | فیلد الزامی است. |
| `readOnly` | boolean | فیلد فقط‌خواندنی است. |
| `defaultValue` | هر مقدار | مقدار پیش‌فرض. |
| `min`، `max` | عدد | محدوده‌ی عدد. |
| `minLength`، `maxLength` | عدد صحیح ≥ ۰ | محدوده‌ی طول متن. |
| `options` | آرایه با حداقل یک گزینه | گزینه‌های `select` و `radio`؛ برای این دو الزامی. |
| `variant` | `info`، `success`، `warning`، `error` | نوع پیام `message`. |

هر گزینه‌ی `options` این شکل را دارد:

| فیلد | اجباری | نوع |
| --- | --- | --- |
| `label` | بله | [متن](#localized-text)، غیرخالی |
| `value` | بله | رشته، عدد یا boolean |

## دکمه‌ی ثبت (submit) {#submit}

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `label` | [متن](#localized-text)، غیرخالی | متن دکمه‌ی ثبت. |
| `closeOnSuccess` | boolean | modal پس از پاسخ موفق بسته شود. |
| `successMessage` | [متن](#localized-text) | پیام موفقیت. |

## متن‌های سه‌زبانه {#localized-text}

همه‌ی فیلدهای متنی (عنوان، توضیح، برچسب، متن راهنما، متن پیام و عنوان گزینه) می‌توانند **رشته‌ی ساده** یا **شیء سه‌زبانه** باشند. رشته‌ی ساده در هر سه زبان بدون تغییر نمایش داده می‌شود.

```json title="شیء سه‌زبانه"
{
  "fa": "ثبت درخواست",
  "en": "Submit request",
  "ar": "إرسال الطلب"
}
```

```json title="در یک فیلد"
{
  "type": "text",
  "key": "subject",
  "label": {
    "fa": "عنوان",
    "en": "Subject",
    "ar": "العنوان"
  }
}
```

- شیء سه‌زبانه فقط کلیدهای `fa`، `en` و `ar` را می‌پذیرد و دست‌کم یکی از آن‌ها را لازم دارد. لازم نیست هر سه را بنویسی.
- فیلدهایی که «غیرخالی» هستند (مثل `title`، عنوان بخش، `submit.label` و `label` گزینه‌ها) باید رشته‌ی غیرخالی باشند، یا در شیء سه‌زبانه دست‌کم یک زبان مقدار غیرخالی داشته باشد.
- دیدار زبان فعال کاربر را انتخاب می‌کند. اگر ترجمه‌ی همان زبان نباشد، به‌ترتیب از فارسی، انگلیسی و عربی استفاده می‌شود.

## محدودیت‌ها {#limits}

| قاعده | مقدار |
| --- | --- |
| تعداد بخش‌ها | ۱ تا ۲۰ |
| تعداد آیتم‌های هر بخش | ۱ تا ۵۰ |
| `id` بخش‌ها | یکتا در کل ساختار |
| `key` فیلدها | یکتا در کل ساختار |
| `select` و `radio` | حداقل یک گزینه در `options` |
| `link` | فقط آدرس با پروتکل `http` یا `https` |
| `message` | `text` الزامی |

دیدار فقط آیتم‌های همین فهرست را رندر می‌کند و هیچ HTML یا اسکریپتی را که داخل ساختار باشد اجرا نمی‌کند. ساختار نامعتبر رندر نمی‌شود.

## نمونه‌ی پنل اطلاعاتی {#details-example}

پنلی با `layout` برابر `details` که مقدارهایش را هنگام باز شدن از سرور تو می‌گیرد:

```json title="panel.json"
{
  "schemaVersion": 1,
  "layout": "details",
  "title": "اطلاعات سرویس",
  "loadOnOpen": true,
  "sections": [
    {
      "id": "service",
      "items": [
        { "type": "value", "key": "plan", "label": "پلن" },
        { "type": "value", "key": "status", "label": "وضعیت" },
        { "type": "divider" },
        {
          "type": "link",
          "label": "مشاهده در اپلیکیشن",
          "url": "https://example.com/customer"
        }
      ]
    }
  ]
}
```

## نسخه‌بندی {#versioning}

- مقدار `schemaVersion` را همیشه بفرست.
- هر تغییر ناسازگار با افزایش `schemaVersion` انجام می‌شود و نسخه‌ی قبلی تا پایان دوره‌ی مهاجرت قابل استفاده می‌ماند.
- ویژگی اختیاری تازه‌ای که رفتار موجود را تغییر ندهد ممکن است در همان نسخه اضافه شود؛ برای همین فیلد ناشناخته را مبنای منطق اپ خودت قرار نده.

## امنیت {#security}

- هیچ راز، کلید خصوصی یا توکن دائمی را داخل ساختار JSON نگذار؛ این فایل به مرورگر کاربر می‌رسد.
- اعتبارسنجی فرم در دیدار جای اعتبارسنجی سمت سرور تو را نمی‌گیرد. مقادیری که به endpoint تو می‌رسند ورودی کاربرند و باید دوباره چک شوند. [قرارداد endpoint](/api-app-endpoints#json-extension)
