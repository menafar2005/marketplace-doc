## Links چیست؟ {#what}

Link یک گزینه در منوی عملیات دیدار است که وقتی کاربر آن را انتخاب می‌کند، یک صفحه از سایت تو باز می‌شود. برخلاف بقیه‌ی اکستنشن‌ها، کار اصلی بیرون از دیدار و روی سایت خودت انجام می‌شود؛ دیدار فقط نقطه‌ی شروع است و به پلاگین تو می‌گوید کاربر از کجا و برای کدام رکوردها آمده.

Links وقتی مناسب است که پلاگین تو از قبل یک وب‌اپ کامل دارد و کار کاربر آنجا طبیعی‌تر انجام می‌شود. چند مثال:

- ساختن پیش‌فاکتور برای یک معامله در سیستم فروش تو،
- افزودن چند شخص انتخاب‌شده به یک لیست ایمیل،
- باز کردن پرونده‌ی همان مشتری در سیستم پشتیبانی تو.

اگر می‌خواهی کاربر داخل دیدار بماند، [JSON modal](/json-modals) (فرم آماده) یا [Custom modal](/custom-modals) (UI خودت داخل دیدار) را ببین.

## در UI دیدار کجاست؟ {#visibility}

Links در منوی عملیات دو نوع صفحه ظاهر می‌شود:

- **صفحه‌های جزئیات** (Deal details، Person details، Organization details، Case details): در منوی ⋯ همان رکورد. اکستنشن روی همان یک رکورد اجرا می‌شود.
- **صفحه‌های لیست** (Deals list، People list، Organizations list، Case list): کاربر یک یا چند ردیف را انتخاب می‌کند، روی ⋯ کنار عملیات گروهی می‌زند و گزینه‌ی پلاگین را انتخاب می‌کند. بدون انتخاب ردیف، گزینه در دسترس نیست. اکستنشن روی همه‌ی ردیف‌های انتخاب‌شده اجرا می‌شود.

![اکشن پلاگین در منوی عملیات صفحه‌ی جزئیات معامله](/images/extensions/action-menu-deal.webp "صفحه‌ی جزئیات: گزینه‌ی پلاگین داخل منوی ⋯ همان رکورد")

![اکشن پلاگین در لیست معاملات روی ردیف‌های انتخاب‌شده](/images/extensions/action-menu-list.webp "صفحه‌ی لیست: بعد از انتخاب ردیف‌ها، گزینه‌ی پلاگین در منوی ⋯ کنار عملیات گروهی")

هر پلاگین در هر Location منو حداکثر ۳ اکستنشن از نوع Links، JSON modal و Custom modal دارد و در کل حداکثر ۱۸. [ظرفیت‌ها](/app-extensions#limits)

## Links چطور کار می‌کند؟ {#how}

1. کاربر گزینه‌ی پلاگین را از منو انتخاب می‌کند.
2. دیدار یک `launchCode` برای همین اجرا می‌سازد و URLی را که ثبت کرده‌ای با آن باز می‌کند.
3. سرور تو `launchCode` را به [Runtime Token](/runtime-token) تبدیل می‌کند و از `context.entityIds` می‌فهمد کاربر کدام رکوردها را انتخاب کرده.
4. صفحه‌ی پلاگین تو با داده‌ی همان رکوردها نمایش داده می‌شود.

```http title="آدرسی که دیدار باز می‌کند"
GET https://your-app.example.com/didar/invoice?launchCode=ONE_TIME_CODE
```

مثلاً اگر کاربر در لیست معاملات دو ردیف را انتخاب کرده باشد، context بعد از تبادل این شکلی است:

```json title="context بعد از تبادل (از لیست معاملات، دو ردیف انتخاب‌شده)"
{
  "target": "extension",
  "runtimeId": "RUNTIME_ID",
  "location": 1,
  "entityType": "deal",
  "entityIds": ["DEAL_ID_1", "DEAL_ID_2"],
  "payload": {}
}
```

> [!WARNING]
> شناسه‌ی رکوردها را فقط از `context.entityIds` بگیر. هیچ شناسه‌ای در خود URL به پلاگین تو نمی‌رسد و نباید هم برسد؛ اگر کاربر بتواند شناسه را در آدرس عوض کند، می‌تواند به رکوردی برسد که حق دیدنش را ندارد.

بعد از باز شدن صفحه، کاربر روی سایت توست. اگر در همان صفحه کارهای بیشتری انجام می‌دهد (فرم پر می‌کند، دکمه می‌زند)، Runtime Token را به مرورگر نفرست؛ یک session کوتاه سمت سرور بساز و درخواست‌های داده را از backend بفرست. یادت باشد token فقط چند دقیقه عمر می‌کند. [الگوی session کوتاه](/custom-ui-extensions#security)

## Links را چطور اضافه کنم؟ {#add}

در Developer Hub، تب **App extensions**، کارت **Links** را انتخاب کن و **Add** بزن.

| فیلد | توضیح |
| --- | --- |
| Action name **(الزامی)** | متنی که در منوی عملیات دیده می‌شود؛ حداکثر ۳۰ کاراکتر. کوتاه و فعلی بنویس، مثل «صدور پیش‌فاکتور». |
| Action description | اختیاری؛ حداکثر ۱۵۰ کاراکتر. |
| URL **(الزامی)** | آدرس صفحه‌ی پلاگین تو؛ URL معتبر. دیدار `?launchCode=…` را به آن اضافه می‌کند. |
| JWT secret **(الزامی)** | یک رشته‌ی تصادفی طولانی که فقط روی سرور تو می‌ماند. [توضیح](/custom-ui-extensions#jwt-secret) |
| Locations **(الزامی)** | صفحه‌هایی که گزینه در منویشان ظاهر می‌شود؛ حداقل یکی، و حداکثر ۳ اکستنشن منو در هر Location. |

سپس Save اصلی صفحه را بزن؛ Save مودال فقط تغییر موقت است.

## تمپلیت کد {#template}

این تمپلیت یک صفحه‌ی «پیش‌فاکتور» است که روی یک یا چند معامله‌ی انتخاب‌شده کار می‌کند: `launchCode` را تبدیل می‌کند، همه‌ی معامله‌های `entityIds` را از دیدار می‌خواند و یک صفحه‌ی HTML نشان می‌دهد. آدرس آن (`/didar/invoice`) را در فیلد URL ثبت کن. scope لازم: **Deals · Read only**. از کلاینت مشترک [Runtime Token](/runtime-token#template) استفاده می‌کند.
