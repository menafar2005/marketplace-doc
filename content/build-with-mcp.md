## ۱. MCP را وصل کن {#connect}

<!--MCP_TABS-->

> [!NOTE]
> این MCP احراز هویت لازم ندارد (اگر ابزارت نوع Authentication را پرسید، **None** را انتخاب کن)، فقط داک را می‌خواند و هیچ داده‌ی CRM یا secretی را لمس نمی‌کند. آدرس بالا همین سایت است و برای همین داک ساخته شده؛ با هر تغییر داک در GitHub، MCP هم به‌روز می‌شود.

## MCP چه چیزهایی بلد است {#tools}

MCP فقط از محتوای همین داک جواب می‌دهد تا با داک تناقض نداشته باشد، و هر جوابش لینک صفحه‌ی مرجع را دارد.

| ابزار | کار |
| --- | --- |
| `search_docs` | جستجو در کل داک و برگرداندن تکه‌های مرتبط با لینک صفحه |
| `get_page` | متن کامل یک صفحه به Markdown |
| `list_pages` | فهرست همه‌ی صفحه‌ها |
| `get_plugin_anatomy` | بخش‌های پلاگین، قواعد هرکدام و صفحه‌ی مرجع |
| `get_api_spec` | مشخصات دقیق هر endpoint (نصب، توکن و داده): مسیر، scope، پارامترها، نمونه درخواست و پاسخ |
| `list_scopes` | scopeها و دسترسی هرکدام |
| `list_extensions` | نوع محتوا، surface و locationهای اکستنشن |
| `list_error_codes` | HTTP statusها و کدهای خطا |
| `scaffold_plugin` | اسکلت backend اپ (نصب، launch، تبادل token، فراخوانی API) |
| `validate_plugin` | چک تنظیمات اپ در برابر قواعد داک، پیش از نصب |

علاوه بر ابزارها، هر صفحه‌ی داک به‌شکل resource (`didar-docs://<slug>`) هم در دسترس است.

## ۲. اولین پلاگین را بساز {#build}

| قدم | چه کار کنی |
| --- | --- |
| ۱. نیازت را با یک جمله بگو | چه کاری، برای کدام داده‌ی دیدار، و کجای UI. |
| ۲. اسکلت را بگیر و اجرا کن | MCP با `scaffold_plugin` backend را با بخش‌های استاندارد می‌سازد. |
| ۳. پیش از نصب چک کن | از MCP بخواه با `validate_plugin` تنظیمات را بررسی کند. |

**prompt نمونه**

> با MCP دیدار یک اپ بساز که در جزئیات معامله یک فرم JSON نشان بدهد، با submit آن یک یادداشت روی همان معامله ثبت کند. قبل از تحویل، تنظیمات را با validate_plugin چک کن.
