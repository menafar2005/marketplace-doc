## شش مفهوم در یک نگاه {#overview}

| مفهوم | چند بار ساخته می‌شود | چه چیزی دارد |
| --- | --- | --- |
| **اپ** | یک‌بار، در Developer Hub | Client ID و Client secret، Callback URL، scopeها، اکستنشن‌ها |
| **نصب** | یک‌بار برای هر BizDomain | اتصال اپ به یک کسب‌وکار با scopeهایی که ادمین تأیید کرده |
| **اجرا** | هر بار که کاربر اکستنشن را باز می‌کند | launchCode ← Runtime Token و Runtime Context ← درخواست به API پروکسی |

## ۱. اپ (App) {#app}

تعریف پلاگین تو در دیدار. آن را یک‌بار در **Developer Hub** می‌سازی و این‌ها را برایش مشخص می‌کنی:

- **نام** و **Callback URL**: آدرسی روی سرور تو که دیدار بعد از نصب، کاربر را به آن برمی‌گرداند.
- **scopeها**: به چه داده‌هایی نیاز داری.
- **اکستنشن‌ها**: اپ کجای دیدار دیده شود.

Developer Hub در عوض به تو یک **Client ID** (شناسه‌ی عمومی اپ) و یک **Client secret** (رمز اپ) می‌دهد. سرور تو با این دو، هویت اپ را به دیدار ثابت می‌کند. اپ یا **Draft** است (در حال ساخت) یا **Live** (قابل نصب برای همه‌ی کسب‌وکارها).

## ۲. نصب (Installation) {#installation}

اپ به‌تنهایی به داده‌ی هیچ کسب‌وکاری دسترسی ندارد. وقتی ادمین یک BizDomain لینک نصب را باز می‌کند و تأیید می‌کند، یک **نصب** ساخته می‌شود: اپ تو به همان BizDomain وصل می‌شود، با همان scopeهایی که ادمین دید و پذیرفت.

یک اپ می‌تواند روی ده‌ها BizDomain نصب باشد؛ هر نصب مستقل است و با `BizDomainId` شناخته می‌شود.

## ۳. Scope (دسترسی) {#scope}

scope تعیین می‌کند اپ به کدام داده دسترسی دارد. در Developer Hub برای هر بخش یکی از دو سطح را انتخاب می‌کنی:

| در Developer Hub | scope خواندن (Read only) | scope خواندن و نوشتن (Full access) |
| --- | --- | --- |
| Access to basic information (همیشه فعال) | `basicinfo` | — |
| Deals | `deals` | `deals.fullaccess` |
| Cases | `cases` | `cases.fullaccess` |
| Contacts | `contacts` | `contacts.fullaccess` |
| Activities | `activities` | `activities.fullaccess` |

فقط چیزی را بخواه که واقعاً لازم داری؛ ادمین هنگام نصب همین فهرست را می‌بیند.

## ۴. اکستنشن (Extension) {#extension}

جایی از UI دیدار که اپ تو در آن ظاهر می‌شود: یک گزینه در منوی عملیات، یک پنل در صفحه‌ی جزئیات، یا صفحه‌ی تنظیمات اپ. محل دقیق هر اکستنشن را **Location** می‌گوییم (مثلاً «جزئیات معامله» یا «لیست اشخاص»). جزئیات در [اکستنشن‌ها](/extensions).

## ۵. اجرا: launchCode و Runtime Token {#runtime}

مهم‌ترین مفهوم مارکت‌پلیس همین است. هر بار که کاربر یک اکستنشن را باز می‌کند:

1. دیدار یک **launchCode** می‌سازد: کدی کوتاه‌عمر و یک‌بارمصرف. آن را به آدرس اکستنشن تو اضافه می‌کند، مثلاً `https://your-app.example.com/launch?launchCode=…`
2. سرور تو این کد را همراه Client ID و Client secret به مارکت‌پلیس می‌فرستد.
3. مارکت‌پلیس یک **Runtime Token** (یک JWT که چند دقیقه اعتبار دارد) و یک **Runtime Context** برمی‌گرداند.

Runtime Context می‌گوید این اجرا دقیقاً چیست: کدام اکستنشن، در کدام Location، روی کدام رکوردها (`entityIds`) و با چه مقادیری از فرم (`payload`).

> [!NOTE]
> **چرا این‌قدر پیچیده؟** چون هیچ چیز حساسی نباید در URL یا مرورگر باشد. مرورگر فقط یک کد بی‌ارزش و یک‌بارمصرف را جابه‌جا می‌کند؛ token واقعی فقط بین سرور تو و مارکت‌پلیس رد و بدل می‌شود.

## ۶. API پروکسی {#proxy}

سرور تو مستقیم به API دیدار وصل نمی‌شود. همه‌ی درخواست‌های داده از `https://marketplace.didar.me` با هدر `Authorization: Bearer <Runtime Token>` فرستاده می‌شوند. مارکت‌پلیس هر درخواست را دو بار چک می‌کند و بعد به دیدار می‌فرستد:

- **scope:** آیا اپ اجازه‌ی این نوع داده را دارد؟
- **context:** آیا این رکورد جزو `entityIds` همین اجراست؟

پس اگر کاربر اکستنشن را روی معامله‌ی A اجرا کرده، اپ نمی‌تواند معامله‌ی B را بخواند، حتی با scope کامل.

## واژه‌نامه {#glossary}

| اصطلاح | معنی |
| --- | --- |
| BizDomain | فضای کاری یک کسب‌وکار در دیدار (tenant). هر نصب به یک BizDomain وصل است. |
| Developer Hub | بخشی از دیدار برای ساخت و مدیریت اپ‌ها؛ فقط برای ادمین BizDomain. |
| Client ID / Client secret | شناسه‌ی عمومی و رمز اپ. secret فقط روی سرور تو. |
| Callback URL | آدرس HTTPS اپ که دیدار بعد از تأیید نصب، `code` نصب را به آن می‌فرستد. |
| لینک نصب (Install link) | آدرسی که ادمین را به صفحه‌ی تأیید نصب اپ می‌برد؛ در Developer Hub با Share install link. |
| ApiKey (کلید نصب) | کلیدی که بعد از تکمیل نصب می‌گیری؛ فقط رمزگذاری‌شده نگه‌داری می‌شود. |
| state | مقدار تصادفی یک‌بارمصرفی که اپ پیش از فرستادن کاربر به نصب می‌سازد و در callback مقایسه می‌کند. |
| Location | محل اجرای اکستنشن در UI دیدار، مثل «جزئیات معامله». |
| launchCode | کد یک‌بارمصرف و کوتاه‌عمری که دیدار هنگام اجرای اکستنشن به URL اپ اضافه می‌کند. |
| Runtime Token | JWT کوتاه‌عمری که سرور اپ با launchCode می‌گیرد؛ فقط برای همان اجرا. |
| Runtime Context | `target`، `runtimeId`، `location`، `entityType`، `entityIds` و `payload` همان اجرا. |
| payload | مقادیری که کاربر در فرم JSON وارد کرده؛ ورودی غیرقابل‌اعتماد است. |
| envelope | قالب استاندارد پاسخ مارکت‌پلیس: `succeeded`، `data`، `error`، `meta`. |
| traceId | شناسه‌ی پیگیری یک درخواست برای پشتیبانی. |
